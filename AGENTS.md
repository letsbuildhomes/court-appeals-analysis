# Collaboration preference

Answer the user's questions in chat. A question about a possible change, where
to record a decision, or how to do something is not an instruction to make
that change. Edit files, run a pipeline, or take other actions that change
state only when the user directly asks for the action. Read-only investigation
is fine when needed to answer a question.

# Issues

Open questions, known problems and planned work live in `docs/issues/`, one
file per issue; `docs/issues/README.md` has the format. Check them before
starting work, and record new issues and outcomes there.
